# Plan: PTL-0037 DNS Resolution Failure Troubleshooting

## 1. Overview & Scope
- **ID:** PTL-0037
- **Title:** DNS Resolution Failure Troubleshooting
- **Category:** `network-services`
- **Difficulty:** `beginner`
- **Scope:** Diagnose wrong DNS client settings, missing DNS host (A) records, disabled DNS services, and client name-resolution errors.
- **Acceptance:** Direct IP connectivity works while domain name resolution fails; systematic diagnosis and correction restores full FQDN name resolution and web portal access.
- **Prerequisites:** `PTL-0022` (DNS Records and HTTP Web Services).

## 2. Topology Design
- **Router:** `R1` (Cisco 4321 ISR)
  - `GigabitEthernet0/0/0`: `192.168.1.1/24` (Uplink to Client LAN Switch `S1` Fa0/1)
  - `GigabitEthernet0/0/1`: `192.168.2.1/24` (Uplink to Server Farm Switch `S2` Fa0/1)
- **Switches:**
  - `S1` (Cisco Catalyst 2960-24TT): Client access switch connecting `PC-1` (Fa0/2) and `PC-2` (Fa0/3).
  - `S2` (Cisco Catalyst 2960-24TT): Server farm switch connecting `DNS-Server` (Fa0/2) and `Web-Server` (Fa0/3).
- **Servers:**
  - `DNS-Server` (`Server-PT`): IP `192.168.2.10/24`, Gateway `192.168.2.1`. Runs Cisco Packet Tracer DNS service.
  - `Web-Server` (`Server-PT`): IP `192.168.2.20/24`, Gateway `192.168.2.1`. Runs Cisco Packet Tracer HTTP service ("Welcome to Corporate Intranet").
- **Clients:**
  - `PC-1` (`PC-PT`): IP `192.168.1.10/24`, Gateway `192.168.1.1`.
  - `PC-2` (`PC-PT`): IP `192.168.1.20/24`, Gateway `192.168.1.1`.

## 3. Injected Faults (Starter State)
1. **Fault 1 (Misconfigured Client DNS Server IP on PC-1):**
   - `PC-1` has DNS Server set to `192.168.2.99` (non-existent IP).
   - *Symptom:* `PC-1` pings `192.168.2.20` directly via IP address (100% success), but `nslookup corpweb.local` fails with `DNS request timed out`.
2. **Fault 2 (Missing Host A Record on DNS-Server for PC-2 target):**
   - `PC-2` has correct DNS Server `192.168.2.10`.
   - `DNS-Server` has A record for `corpweb.local` (`192.168.2.20`), but is MISSING the A record for `portal.corpweb.local`.
   - *Symptom:* `PC-2` can resolve `corpweb.local`, but resolving `portal.corpweb.local` fails with `*** Can't find portal.corpweb.local: No answer`.
3. **Fault 3 (DNS Service Disabled on DNS-Server):**
   - In baseline starter state, DNS service process on `DNS-Server` is set to `disabled` (`setEnable(false)`).
   - *Symptom:* Neither client can resolve any domain names until the service is started.

## 4. Completed State (Repaired State)
- `DNS-Server` has DNS service ENABLED (`setEnable(true)`).
- `DNS-Server` has complete records:
  - `corpweb.local` -> `192.168.2.20` (A Record)
  - `portal.corpweb.local` -> `192.168.2.20` (A Record)
  - `www.corpweb.local` -> `corpweb.local` (CNAME Record)
- `PC-1` has DNS Server corrected to `192.168.2.10`.
- `PC-2` has DNS Server confirmed as `192.168.2.10`.
- All clients can successfully resolve all FQDNs via `nslookup` and ping them by name.

## 5. Test Matrix
- **POS-01:** `R1` routing and interface state (`Gi0/0/0` and `Gi0/0/1` up/up, routing active).
- **POS-02:** `DNS-Server` and `Web-Server` IP reachability from clients via direct IP.
- **POS-03:** `DNS-Server` service state active with verified database entries (`corpweb.local`, `portal.corpweb.local`, `www.corpweb.local`).
- **POS-04:** `PC-1` DNS resolution of `corpweb.local` via `nslookup` (resolves `192.168.2.20`).
- **POS-05:** `PC-1` ping `corpweb.local` by FQDN (100% success).
- **POS-06:** `PC-2` DNS resolution of `portal.corpweb.local` via `nslookup` (resolves `192.168.2.20`).
- **POS-07:** `PC-2` DNS resolution of CNAME `www.corpweb.local` (resolves to `corpweb.local` -> `192.168.2.20`).
- **NEG-01:** `PC-1` querying wrong DNS server (`192.168.2.99`) fails with `DNS request timed out`.
- **NEG-02:** `PC-2` querying missing record (`unknown.corpweb.local`) fails with `No answer` / non-existent domain.
