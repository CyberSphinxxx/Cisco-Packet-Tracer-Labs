# Lab Design Plan: PTL-0036 - Wireless VLAN Separation and Guest Access

## 1. Metadata and Identification
- **Lab ID:** PTL-0036
- **Slug:** `wireless-vlan-separation-and-guest-access`
- **Category:** `wireless-wan`
- **Difficulty:** `intermediate`

- **Prerequisites:** `["PTL-0035"]`

## 2. Learning Objectives
1. Design and implement multi-VLAN segmentation to isolate corporate internal staff traffic from untrusted guest users.
2. Configure 802.1Q trunking on a Cisco Catalyst 2960 switch and Router-on-a-Stick subinterfaces on a Cisco 4321 ISR.
3. Deploy autonomous wireless access points (`AccessPoint-PT`) mapped to separate access VLANs (VLAN 10 Corporate, VLAN 20 Guest).
4. Configure multiple Cisco IOS DHCP pools to service both corporate and guest subnets automatically.
5. Implement Cisco IOS Extended Access Control Lists (ACLs) to enforce boundary security: permitting guests access to the public DMZ web services while strictly denying guest access to corporate staff servers and hosts.
6. Verify positive connectivity for corporate and guest clients to permitted destinations and verify negative blocking of unauthorized guest lateral movement.

## 5. Security & Access Control Configuration
- **Access Points:**
  - `AP-Corp`: SSID `CORP-NET`, WPA2-Personal (PSK / AES), Passphrase `CorpWifiPass2026!`
  - `AP-Guest`: SSID `GUEST-NET`, WPA2-Personal (PSK / AES), Passphrase `GuestWifiPass2026!`
- **Access Control List (`GUEST-RESTRICTION`) on `Edge-R1`:**
  ```cisco
  ip access-list extended GUEST-RESTRICTION
   remark Permit DHCP requests from guests to local router
   permit udp any any eq bootps
   remark Permit DNS queries to DMZ server
   permit udp any host 192.168.30.100 eq domain
   remark Permit Web traffic (HTTP/HTTPS) to DMZ server
   permit tcp any host 192.168.30.100 eq www
   permit tcp any host 192.168.30.100 eq 443
   remark Permit ICMP diagnostics to DMZ server
   permit icmp any host 192.168.30.100
   remark Explicitly deny guest access to Corporate Staff VLAN 10
   deny ip 192.168.20.0 0.0.0.255 192.168.10.0 0.0.0.255
   remark Permit guest access to any other external networks
   permit ip 192.168.20.0 0.0.0.255 any
  ```
  Applied to subinterface `Gi0/0/0.20`:
  `ip access-group GUEST-RESTRICTION in`

## 6. Test and Verification Matrix
- **POS-01:** Subinterfaces `Gi0/0/0.10` and `Gi0/0/0.20` active with correct 802.1Q encapsulation on `Edge-R1`.
- **POS-02:** `Switch-S1` trunk active on `Gi0/1`, `Fa0/1` in VLAN 10, `Fa0/2` in VLAN 20, `Fa0/3` in VLAN 10 with `spanning-tree portfast` enabled on AP ports.
- **POS-03:** `Edge-R1` DHCP pools (`CORP-POOL` and `GUEST-POOL`) active and leasing addresses with correct gateways.
- **POS-04:** `Corp-Laptop` associates to `CORP-NET` and leases `192.168.10.11`.
- **POS-05:** `Corp-Laptop` successfully reaches internal staff target `Corp-Server` (`192.168.10.100`) via ICMP (100% success).
- **POS-06:** `Corp-Laptop` successfully reaches public/DMZ target `Web-Server` (`192.168.30.100`) via ICMP (100% success).
- **POS-07:** `Guest-Laptop` associates to `GUEST-NET` and leases `192.168.20.11`.
- **POS-08:** `Guest-Laptop` successfully reaches default gateway `192.168.20.1` and public target `Web-Server` (`192.168.30.100`) (100% success).
- **NEG-01:** `Guest-Laptop` attempts to reach internal staff target `Corp-Server` (`192.168.10.100`) -> Denied by ACL `GUEST-RESTRICTION`, 0% success (100% packet loss).
- **NEG-02:** `Guest-Laptop` attempts to ping `Corp-Laptop` (`192.168.10.11`) -> Denied by ACL `GUEST-RESTRICTION`, 0% success.
