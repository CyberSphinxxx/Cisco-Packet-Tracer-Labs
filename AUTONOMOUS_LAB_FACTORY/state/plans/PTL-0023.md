# Lab Implementation Plan: PTL-0023 NTP and Syslog Network Monitoring

## 1. Metadata & Identification
- **Lab ID:** PTL-0023
- **Title:** NTP and Syslog Network Monitoring
- **Category:** network-services
- **Difficulty:** intermediate
- **Estimated Duration:** 60 minutes
- **Canonical Directory:** `labs/network-services/ntp-and-syslog-network-monitoring`
- **Slug:** `ntp-and-syslog-network-monitoring`

## 2. Educational & Technical Objectives
- **Scope:** Configure router clock synchronization using Network Time Protocol (NTP) and centralized message logging via Syslog to a dedicated management server.
- **Target Audience:** CCNA / Network Engineers learning network operations, time synchronization, and centralized observability.
- **Acceptance Criteria:**
  - NTP client association established with the time server (`192.168.1.100`).
  - Accurate timestamping enabled on log messages with millisecond resolution (`service timestamps log datetime msec`).
  - Syslog messages forwarded to centralized `LogServer` (`192.168.1.100`).
  - Administrative state changes (such as loopback or interface state events) trigger immediate informational syslog entries on the remote server.

## 3. Topology & IP Addressing Plan
### 3.1 Devices & Interfaces
- **R1** (Cisco 4321):
  - `GigabitEthernet0/0/0`: `192.168.1.1/24` (Connects to S1 `GigabitEthernet0/1`)
  - `Loopback0`: `10.1.1.1/24` (Administrative test interface for event generation)
- **S1** (Cisco 2960):
  - `GigabitEthernet0/1`: Connected to `R1` `G0/0/0`
  - `FastEthernet0/1`: Connected to `PC-Admin` `FastEthernet0`
  - `FastEthernet0/2`: Connected to `LogServer` `FastEthernet0`
- **PC-Admin** (PC-PT):
  - `FastEthernet0`: `192.168.1.10/24`, Gateway: `192.168.1.1`
- **LogServer** (Server-PT):
  - `FastEthernet0`: `192.168.1.100/24`, Gateway: `192.168.1.1`
  - Services: `NtpServer` (enabled), `SyslogServer` (enabled)

## 4. Configuration Steps
### 4.1 Starter State
- Basic interface addressing on R1 and PCs.
- Basic Layer 2 connectivity across S1.
- NTP and Syslog services disabled on R1.
- Server services enabled on LogServer.

### 4.2 Completed State
- On R1:
  - `service timestamps log datetime msec`
  - `service timestamps debug datetime msec`
  - `ntp server 192.168.1.100`
  - `logging host 192.168.1.100`
  - `logging trap informational`
  - `logging source-interface GigabitEthernet0/0/0`
  - `logging buffered 64000 informational`

## 5. Verification Matrix
- **POS-01:** Basic IP Reachability (PC-Admin and LogServer can reach R1 G0/0/0 at 192.168.1.1).
- **POS-02:** NTP Synchronization (`show ntp associations` lists 192.168.1.100).
- **POS-03:** Syslog Local Logging Configuration (`show logging` displays trap logging to 192.168.1.100 with millisecond timestamps).
- **POS-04:** Syslog Remote Server Capture (`LogServer` receives logs forwarded over UDP 514).
- **NEG-01:** Fault/State Change Detection (shutting down and bringing up Loopback0 generates `%LINK-5-CHANGED` / `%LINEPROTO-5-UPDOWN` captured on LogServer).
- **NEG-02:** Unreachable NTP Server Handling (invalid NTP configuration behavior verified).
- **Reload Proof:** Starter and Completed `.pkt` files reload cleanly without loss of topology or configurations.
