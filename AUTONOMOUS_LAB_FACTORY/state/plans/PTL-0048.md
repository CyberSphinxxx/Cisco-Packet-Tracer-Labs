## Problem Statement & Educational Value
In enterprise networks, organizations frequently interconnect geographically separated branch offices with a central headquarters (HQ) data center using dedicated point-to-point WAN links. In a classic hub-and-spoke WAN architecture:
1. **Spoke Routers** typically utilize a default route (`0.0.0.0/0`) directing all non-local traffic upstream to the HQ hub router.
2. **The Hub Router** must maintain explicit static routing entries for every spoke branch LAN to enable bidirectional return paths.
3. **Inter-Branch Communication** must transit the hub router (spoke-to-spoke routing), requiring routing symmetry at all hops.

Common operational faults include:
- **Asymmetric / Missing Return Routes**: Spoke sends traffic to HQ, but HQ lacks a route to the spoke LAN, resulting in dropped return packets.
- **Unreachable Next-Hop IPs**: A static route configured with a next-hop address outside the directly connected WAN subnet fails next-hop recursion and is omitted from the routing table.
- **Endpoint Gateway Misconfigurations**: Endpoints configured with incorrect default gateways cannot forward packets outside their local broadcast domain.

In this lab, learners investigate a 3-site enterprise topology (HQ, Branch 1, Branch 2), diagnose missing and misconfigured static routes, repair invalid next-hop parameters, and verify end-to-end spoke-to-hub and spoke-to-spoke reachability.

## Fault Injection in Starter State
1. **Fault 1 (Missing Return Route on R-HQ)**: Route `10.30.0.0 255.255.255.0 172.16.13.2` is omitted on R-HQ, causing traffic to/from Branch 2 to be dropped at HQ.
2. **Fault 2 (Invalid Next-Hop on R-BR1)**: R-BR1 is configured with `ip route 0.0.0.0 0.0.0.0 172.16.12.5` (invalid IP not on the WAN link), preventing default route installation.
3. **Fault 3 (Default Gateway Misconfiguration on PC-BR1)**: PC-BR1 is configured with gateway `10.20.0.254` instead of `10.20.0.1`.
