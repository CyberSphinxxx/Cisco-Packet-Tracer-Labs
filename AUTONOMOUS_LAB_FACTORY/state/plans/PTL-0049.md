## Problem Statement & Educational Value
In modern campus networks, the distribution layer aggregates traffic from multiple access switches and serves as the Layer 3 default gateway boundary for user and server VLANs. Cisco Catalyst multilayer switches (such as the 3560 series) perform hardware-accelerated wire-speed inter-VLAN routing via Switch Virtual Interfaces (SVIs) and Cisco Express Forwarding (CEF).

However, campus distribution deployments frequently experience subtle configuration defects:
1. **Disabled Global IP Routing**: By default, Catalyst switches operate solely as Layer 2 bridges. If the network administrator configures SVIs and IP addresses without issuing the global `ip routing` command, all inter-VLAN forwarding fails silently while intra-VLAN gateway pings still succeed.
2. **Trunk Allowed-List Omissions**: When 802.1Q trunks between distribution and access switches are manually pruned, omitting a departmental or server VLAN isolates hosts on that switch from the distribution gateway.
3. **Access Port VLAN Misassignment**: Access switchports configured in the wrong VLAN prevent endpoints from reaching their designated subnet gateway.
4. **Native VLAN Alignment**: Trunks must share a common Native VLAN (e.g. VLAN 99) to avoid 802.1Q untagged frame leakage.

In this lab, learners examine a two-tier campus network comprising a Catalyst 3560 distribution switch (`DLS-1`) and two Catalyst 2960 access switches (`ALS-1` and `ALS-2`). Learners audit trunk allowed lists, resolve access port mismatches, activate global IP routing on the distribution core, and verify seamless inter-VLAN communication.

## Topology & Device Layout
- **Distribution Switch:**
  - `DLS-1` (Catalyst 3560-24PS) at x=400, y=160
    - `Gi0/1`: 802.1Q Trunk to `ALS-1 Gi0/1` (native 99, allowed 10,20,30,99)
    - `Gi0/2`: 802.1Q Trunk to `ALS-2 Gi0/1` (native 99, allowed 10,20,30,99)
    - SVIs: `Vlan10`, `Vlan20`, `Vlan30`, `Vlan99`
    - Global: `ip routing`
- **Access Switches:**
  - `ALS-1` (Catalyst 2960-24TT) at x=250, y=300
    - `Gi0/1`: 802.1Q Trunk to `DLS-1 Gi0/1`
    - `Fa0/1`: Access port in VLAN 10 (`PC-Faculty`)
    - `Fa0/2`: Access port in VLAN 20 (`PC-Student`)
    - SVI: `Vlan99` (`192.168.99.11/24`)
  - `ALS-2` (Catalyst 2960-24TT) at x=550, y=300
    - `Gi0/1`: 802.1Q Trunk to `DLS-1 Gi0/2`
    - `Fa0/1`: Access port in VLAN 30 (`Campus-Srv`)
    - SVI: `Vlan99` (`192.168.99.12/24`)
- **Endpoints:**
  - `PC-Faculty` (PC-PT) at x=180, y=440 -> `192.168.10.10/24`, gw `192.168.10.1`
  - `PC-Student` (PC-PT) at x=320, y=440 -> `192.168.20.10/24`, gw `192.168.20.1`
  - `Campus-Srv` (Server-PT) at x=550, y=440 -> `192.168.30.10/24`, gw `192.168.30.1`

## Fault Injection in Starter State
1. **Fault 1 (Disabled IP Routing on Multilayer Switch)**: `no ip routing` on `DLS-1`. The switch cannot forward traffic between SVIs.
2. **Fault 2 (Trunk Allowed-List Omission on ALS-2)**: `switchport trunk allowed vlan 10,20,99` on `ALS-2 Gi0/1` (omitting VLAN 30), isolating the Server Farm.
3. **Fault 3 (Access Port VLAN Misassignment on ALS-1)**: `ALS-1 Fa0/2` assigned to `vlan 1` instead of `vlan 20`, breaking `PC-Student` gateway communication.
