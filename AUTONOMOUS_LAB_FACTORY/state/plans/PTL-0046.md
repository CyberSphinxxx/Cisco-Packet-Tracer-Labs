## Problem Statement & Educational Value
Link aggregation via IEEE 802.3ad / 802.1AX Link Aggregation Control Protocol (LACP) bundles multiple physical Ethernet interfaces into a single logical link (`Port-channel`), multiplying bandwidth and providing seamless link failover. However, Cisco IOS enforces strict port parameter consistency across all member interfaces in an EtherChannel bundle:
1. Port mode must match (all access in the same VLAN, or all trunk).
2. Trunk parameters must match (same Native VLAN and same allowed VLAN list).
3. Physical speed and duplex settings must match.
4. Spanning Tree Protocol costs and path settings must match.

If any physical member interface has an incompatible parameter, LACP detects the discrepancy during BPDU and LACPDU negotiation. Cisco IOS places the mismatched port into a Suspended (`s`) or Standalone state, or flags the bundle as Down (`D`), preventing the port from joining the bundle.

In this lab, learners investigate an operational incident where an inter-switch EtherChannel bundle between distribution switches `SW-1` and `SW-2` is degraded. One of the member interfaces (`Fa0/2` on `SW-2`) was misconfigured with access mode instead of trunk mode, causing LACP to suspend the port and leaving the Port-channel operating in a compromised, single-link state. Learners diagnose the failure using `show etherchannel summary`, `show etherchannel port-channel`, and `show interfaces switchport`, identify the parameter discrepancy, remediate the port configuration, and verify full two-member bundling (`SU`, `P`) and resilient multi-VLAN data transport.

## Topology Design
- **Switches:**
  - `SW-1` (Catalyst 2960-24TT): Distribution Switch 1
  - `SW-2` (Catalyst 2960-24TT): Distribution Switch 2
- **LACP EtherChannel Bundle (Po1):**
  - Aggregating `FastEthernet0/1` and `FastEthernet0/2` between `SW-1` and `SW-2`
  - Active LACP mode: `channel-group 1 mode active` on both switches
  - Trunking: IEEE 802.1Q trunk, Native VLAN 99, Allowed VLANs `10,20,99`
- **Endpoints:**
  - `PC-1` (PC-PT): Connected to `SW-1` `Fa0/10` (VLAN 10: `192.168.10.10/24`)
  - `PC-2` (PC-PT): Connected to `SW-1` `Fa0/20` (VLAN 20: `192.168.20.10/24`)
  - `PC-3` (PC-PT): Connected to `SW-2` `Fa0/10` (VLAN 10: `192.168.10.20/24`)
  - `PC-4` (PC-PT): Connected to `SW-2` `Fa0/20` (VLAN 20: `192.168.20.20/24`)
- **Cabling Matrix:**
  - `SW-1 Fa0/1` <-> `SW-2 Fa0/1` (Copper Crossover)
  - `SW-1 Fa0/2` <-> `SW-2 Fa0/2` (Copper Crossover)
  - `SW-1 Fa0/10` <-> `PC-1 Fa0` (Copper Straight-Through)
  - `SW-1 Fa0/20` <-> `PC-2 Fa0` (Copper Straight-Through)
  - `SW-2 Fa0/10` <-> `PC-3 Fa0` (Copper Straight-Through)
  - `SW-2 Fa0/20` <-> `PC-4 Fa0` (Copper Straight-Through)

## Configuration Matrix
- **Completed State:**
  - `SW-1` & `SW-2`:
    - VLANs 10 (Engineering), 20 (Marketing), 99 (Native_Trunk)
    - `interface range FastEthernet0/1 - 2`:
      - `switchport mode trunk`
      - `switchport trunk native vlan 99`
      - `switchport trunk allowed vlan 10,20,99`
      - `switchport nonegotiate`
      - `channel-group 1 mode active`
    - `interface Port-channel 1`:
      - `switchport mode trunk`
      - `switchport trunk native vlan 99`
      - `switchport trunk allowed vlan 10,20,99`
      - `switchport nonegotiate`
    - Access ports configured with `switchport access vlan <id>` and `spanning-tree portfast`
- **Faulted Starter State:**
  - On `SW-2`, `FastEthernet0/2` is mistakenly configured in access mode:
    - `interface FastEthernet0/2` -> `switchport mode access`, `switchport access vlan 10`, `channel-group 1 mode active`
    - Result: `SW-2 Fa0/2` cannot bundle into trunk `Port-channel 1`. In `show etherchannel summary`, `Fa0/2` shows `(s)` (suspended) or is omitted from bundle, and Port-channel 1 operates in degraded single-link mode.

## Verification Points
- **POS-01:** EtherChannel Logical Interface State: `show etherchannel summary` confirms `Po1(SU)` (Layer 2, in Use) on both `SW-1` and `SW-2`.
- **POS-02:** Member Port Bundling State: `show etherchannel summary` confirms both `Fa0/1(P)` and `Fa0/2(P)` are bundled in Port-channel on both switches.
- **POS-03:** LACP Protocol Negotiation: `show etherchannel port-channel` displays Protocol `LACP`, 2 active ports, and Port-channel operational state.
- **POS-04:** VLAN 10 End-to-End Communication: `PC-1` pings `PC-3` (`192.168.10.20`) with 4/4 echo replies (0% loss).
- **POS-05:** VLAN 20 End-to-End Communication: `PC-2` pings `PC-4` (`192.168.20.20`) with 4/4 echo replies (0% loss).
- **POS-06:** Inter-VLAN Layer 2 Segmentation: `PC-1` ping to `PC-2` (`192.168.20.10`) times out (100% loss).
- **NEG-01:** Starter State Member Mismatch Audit: In starter state, `SW-2# show etherchannel summary` shows `Fa0/2` not bundled in port-channel (suspended `(s)` or down `(D)`), and `Fa0/2` port configuration exhibits mode mismatch (`switchport mode access` vs trunk).
- **NEG-02:** Starter State Degraded Channel State: In starter state, `SW-2# show etherchannel port-channel` reports Number of Ports = 1 (degraded capacity), confirming that the member mismatch prevented dual-link aggregation.
