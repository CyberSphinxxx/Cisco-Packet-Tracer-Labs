# Lab Implementation Plan: PTL-0043 NAT and PAT Troubleshooting Challenge

## 1. Overview & Objectives
- **Lab ID:** PTL-0043
- **Title:** NAT and PAT Troubleshooting Challenge
- **Category:** `network-services`
- **Difficulty:** `intermediate`
- **Estimated Time:** 60 minutes
- **Scope:** Diagnose NAT inside/outside misconfiguration and translation ACL errors on an enterprise edge router connecting dual internal subnets to an ISP.
- **Acceptance:** Failed translation reproduced in starter topology; root causes diagnosed and remediated; active PAT translations and incrementing hit counters verified with live traffic probes across both subnets.

## 2. Topology Design
- **Edge Router:** Cisco ISR 4331 (`Edge-R1`):
  - `GigabitEthernet0/0/0`: Staff LAN (`192.168.10.1/24`) - NAT Inside
  - `GigabitEthernet0/0/1`: Guest LAN (`192.168.20.1/24`) - NAT Inside
  - `GigabitEthernet0/0/2`: WAN Transit Link (`203.0.113.1/30`) - NAT Outside
  - Default route: `ip route 0.0.0.0 0.0.0.0 203.0.113.2`
- **Service Provider Router:** Cisco ISR 4331 (`ISP`):
  - `GigabitEthernet0/0/0`: WAN Transit Link (`203.0.113.2/30`)
  - `GigabitEthernet0/0/1`: Public Internet Subnet (`198.51.100.1/24`)
  - Note: ISP has routing for public subnets only (`203.0.113.0/30` and `198.51.100.0/24`). No route exists for RFC 1918 space (`192.168.0.0/16`).
- **Access Switches:**
  - `Switch-Staff`: Catalyst 2960-24TT (Port `Fa0/1` to `PC-Staff`, `Gi0/1` to `Edge-R1 Gi0/0/0`)
  - `Switch-Guest`: Catalyst 2960-24TT (Port `Fa0/1` to `Laptop-Guest`, `Gi0/1` to `Edge-R1 Gi0/0/1`)
- **Endpoints:**
  - `PC-Staff`: `192.168.10.10/24`, Gateway: `192.168.10.1`
  - `Laptop-Guest`: `192.168.20.10/24`, Gateway: `192.168.20.1`
  - `Web-Server`: `198.51.100.10/24`, Gateway: `198.51.100.1` (HTTP port 80 enabled)

## 3. Fault Injection & Troubleshooting Logic
### Starter Faults (`starter.pkt`):
1. **Translation ACL Error:**
   - Standard ACL 1 is defined as `access-list 1 permit 192.168.1.0 0.0.0.255`.
   - Fault: Typo in subnet address (`192.168.1.0/24` instead of `192.168.10.0/24`), and Guest subnet `192.168.20.0/24` is omitted entirely.
   - Result: Internal packets from `192.168.10.10` and `192.168.20.10` are not matched for translation.
2. **Interface NAT Boundary Misconfigurations:**
   - Interface `GigabitEthernet0/0/1` (Guest LAN) is missing `ip nat inside`.
   - Interface `GigabitEthernet0/0/2` (Outside WAN) is mistakenly configured with `ip nat inside` instead of `ip nat outside`.
   - Result: Packets never traverse inside-to-outside boundaries, NAT translation engine never fires, packets leak untranslated onto the WAN where the ISP drops return traffic.

### Remediated Completed State (`completed.pkt`):
1. **Correct Translation ACL:**
   - `no access-list 1`
   - `access-list 1 permit 192.168.10.0 0.0.0.255`
   - `access-list 1 permit 192.168.20.0 0.0.0.255`
2. **Correct Interface Designations:**
   - `interface GigabitEthernet0/0/0` -> `ip nat inside`
   - `interface GigabitEthernet0/0/1` -> `ip nat inside`
   - `interface GigabitEthernet0/0/2` -> `no ip nat inside`, `ip nat outside`
3. **Dynamic PAT Configuration:**
   - `ip nat inside source list 1 interface GigabitEthernet0/0/2 overload`

## 4. Verification Tests
- **POS-01:** Local IP connectivity: `PC-Staff` pings gateway `192.168.10.1` (4/4, 0% loss); `Laptop-Guest` pings gateway `192.168.20.1` (4/4, 0% loss).
- **POS-02:** NAT Interface Role Verification: `Edge-R1# show ip nat statistics` confirms Inside interfaces are `GigabitEthernet0/0/0` and `GigabitEthernet0/0/1`, and Outside interface is `GigabitEthernet0/0/2`.
- **POS-03:** Translation ACL Verification: `Edge-R1# show access-lists 1` displays active permit statements for `192.168.10.0/24` and `192.168.20.0/24`.
- **POS-04:** Outbound Staff Translation: `PC-Staff` pings `Web-Server` (`198.51.100.10`) with 4/4 echo replies (0% loss).
- **POS-05:** Outbound Guest Translation: `Laptop-Guest` pings `Web-Server` (`198.51.100.10`) with 4/4 echo replies (0% loss).
- **POS-06:** Outbound HTTP Port Translation: `PC-Staff` connects to HTTP port 80 on `Web-Server` (`telnet 198.51.100.10 80`) -> `Open`.
- **POS-07:** Active Translation Table: `Edge-R1# show ip nat translations` confirms both `192.168.10.10` and `192.168.20.10` translated to inside global IP `203.0.113.1` with active port allocations.
- **NEG-01:** Starter State Translation Failure: In `starter.pkt`, `PC-Staff` ping to `198.51.100.10` fails with 100% loss (`Request timed out`).
- **NEG-02:** Starter State Fault Evidence: In `starter.pkt`, `show ip nat translations` is empty, `show ip nat statistics` shows no outside interfaces and 0 hits, and ACL 1 shows `permit 192.168.1.0 0.0.0.255`.
