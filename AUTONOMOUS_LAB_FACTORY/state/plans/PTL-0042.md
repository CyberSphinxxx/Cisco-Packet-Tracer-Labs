# Lab Implementation Plan: PTL-0042 Named Extended IPv4 ACL for Server Access

## 1. Overview & Objectives
- **Lab ID:** PTL-0042
- **Title:** Named Extended IPv4 ACL for Server Access
- **Category:** `network-security`
- **Difficulty:** `intermediate`
- **Estimated Time:** 60 minutes
- **Scope:** Create specific named extended ACLs that permit DNS (UDP 53) and HTTP (TCP 80) access while strictly blocking unauthorized destinations and internal server access.
- **Acceptance:** Traffic matrix validates per-service permissions across guest and staff subnets; `show access-lists` displays active, non-zero match counts on all permitted and denied traffic rules.

## 2. Topology Design
- **Core Router:** Cisco ISR 4331 (`R1`):
  - `GigabitEthernet0/0/0`: Staff LAN (`192.168.10.1/24`)
  - `GigabitEthernet0/0/1`: Guest LAN (`192.168.20.1/24`)
  - `GigabitEthernet0/0/2`: Corporate DMZ (`192.168.100.1/24`)
- **Access Switches:**
  - `SW-Staff`: Catalyst 2960-24TT (Port `Fa0/1` to `PC-Staff`, `Gi0/1` to `R1 Gi0/0/0`)
  - `SW-Guest`: Catalyst 2960-24TT (Port `Fa0/1` to `Laptop-Guest`, `Gi0/1` to `R1 Gi0/0/1`)
  - `SW-Server`: Catalyst 2960-24TT (Port `Fa0/1` to `DNS-Web-Server`, `Fa0/2` to `DB-Server`, `Gi0/1` to `R1 Gi0/0/2`)
- **Endpoints:**
  - `PC-Staff`: `192.168.10.10/24`, GW: `192.168.10.1`
  - `Laptop-Guest`: `192.168.20.10/24`, GW: `192.168.20.1`
  - `DNS-Web-Server`: `192.168.100.10/24`, GW: `192.168.100.1` (DNS service and HTTP service enabled)
  - `DB-Server`: `192.168.100.20/24`, GW: `192.168.100.1` (Confidential database server)

## 3. Traffic Matrix & Security Policy
| Rule ID | Source | Destination | Protocol / Port | Action | Purpose |
|:---|:---|:---|:---|:---|:---|
| **GUEST-01** | Guest LAN (`192.168.20.0/24`) | DNS-Web-Server (`192.168.100.10`) | UDP Port 53 (DNS) | **PERMIT** | Domain name resolution |
| **GUEST-02** | Guest LAN (`192.168.20.0/24`) | DNS-Web-Server (`192.168.100.10`) | TCP Port 80 (HTTP) | **PERMIT** | Public intranet portal |
| **GUEST-03** | Guest LAN (`192.168.20.0/24`) | R1 Gateway (`192.168.20.1`) | ICMP Echo (ping) | **PERMIT** | Local default gateway ping |
| **GUEST-04** | Guest LAN (`192.168.20.0/24`) | DB-Server (`192.168.100.20`) | IP Any | **DENY** | Prohibit guest access to database |
| **GUEST-05** | Guest LAN (`192.168.20.0/24`) | Corporate DMZ (`192.168.100.0/24`) | IP Any | **DENY** | Prohibit all other DMZ access |
| **GUEST-06** | Guest LAN (`192.168.20.0/24`) | Staff LAN (`192.168.10.0/24`) | IP Any | **DENY** | Guest network isolation |
| **GUEST-07** | Guest LAN (`192.168.20.0/24`) | Any External Destination | IP Any | **PERMIT** | Internet access |

## 4. Verification Tests
- **POS-01:** R1 interface operational status (`Gi0/0/0`, `Gi0/0/1`, `Gi0/0/2` all up/up).
- **POS-02:** Laptop-Guest can resolve DNS or ping local gateway `192.168.20.1`.
- **POS-03:** Laptop-Guest can establish HTTP connection to `DNS-Web-Server` (`telnet 192.168.100.10 80`).
- **POS-04:** Laptop-Guest is denied access to `DB-Server` (`ping 192.168.100.20` fails with Destination host unreachable).
- **POS-05:** Laptop-Guest is denied access to Staff LAN (`ping 192.168.10.10` fails with Destination host unreachable).
- **POS-06:** PC-Staff has full access to `DNS-Web-Server` and `DB-Server`.
- **POS-07:** `R1# show access-lists GUEST-FILTER` demonstrates active match counts on permit and deny rules.
- **NEG-01:** Starter state verification: GUEST-FILTER is absent or unapplied; guest can ping DB-Server and Staff LAN violating security policy.
- **NEG-02:** Completed state verification: Unauthorized ICMP or data probes from guest to DB-Server trigger ACL drop.
