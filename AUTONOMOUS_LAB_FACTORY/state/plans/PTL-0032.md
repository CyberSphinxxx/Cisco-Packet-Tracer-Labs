# Lab Design Plan: PTL-0032 - HSRP First-Hop Gateway Failover

## 1. Overview and Rationale
- **Lab ID:** PTL-0032
- **Slug:** `hsrp-first-hop-gateway-failover`
- **Category:** `routing`
- **Difficulty:** Advanced
- **Estimated Minutes:** 60
- **Curriculum Objective:** Provide practical hands-on experience designing, configuring, and verifying First-Hop Redundancy Protocol (FHRP) using Cisco Hot Standby Router Protocol (HSRPv2). Learners configure active and standby router roles with custom priorities and preemption, examine state transitions (`Listen`, `Speak`, `Standby`, `Active`), and execute a live failover scenario to validate uninterrupted end-user default gateway availability.

## 2. Topology and IP Addressing
- **Topology:**
  - `Edge-R1` (Cisco 4321 ISR, x: 220, y: 260) - Primary Default Gateway
  - `Edge-R2` (Cisco 4321 ISR, x: 540, y: 260) - Secondary Default Gateway
  - `Core-R3` (Cisco 4321 ISR, x: 380, y: 120) - Upstream Core Router
  - `Switch-S1` (Catalyst 2960-24TT, x: 380, y: 390) - Enterprise LAN Switch
  - `PC1` (PC-PT, x: 260, y: 500) - LAN Client A
  - `PC2` (PC-PT, x: 500, y: 500) - LAN Client B
  - `Web-Server` (Server-PT, x: 580, y: 120) - External Enterprise Web Server
- **Addressing Plan:**
  - LAN Subnet: `192.168.1.0/24`
    - HSRP Virtual IP (VIP): `192.168.1.1` (HSRP Group 1)
    - `Edge-R1` Gi0/0/1: `192.168.1.2/24`
    - `Edge-R2` Gi0/0/1: `192.168.1.3/24`
    - `Switch-S1` VLAN 1: `192.168.1.5/24`
    - `PC1`: `192.168.1.10/24`, Default Gateway: `192.168.1.1`
    - `PC2`: `192.168.1.20/24`, Default Gateway: `192.168.1.1`
  - Core Transit Link 1 (`Edge-R1` Gi0/0/0 <-> `Core-R3` Gi0/0/0): `10.10.12.0/30`
    - `Edge-R1` Gi0/0/0: `10.10.12.1/30`
    - `Core-R3` Gi0/0/0: `10.10.12.2/30`
  - Core Transit Link 2 (`Edge-R2` Gi0/0/0 <-> `Core-R3` Gi0/0/1): `10.10.23.0/30`
    - `Edge-R2` Gi0/0/0: `10.10.23.1/30`
    - `Core-R3` Gi0/0/1: `10.10.23.2/30`
  - Server Subnet (`Core-R3` Gi0/0/2 <-> `Web-Server` Fa0): `203.0.113.0/24`
    - `Core-R3` Gi0/0/2: `203.0.113.1/24`
    - `Web-Server` Fa0: `203.0.113.100/24`, Default Gateway: `203.0.113.1`

## 3. Routing Architecture
- Interior Gateway Protocol: OSPFv2 Single Area 0 across `Core-R3`, `Edge-R1`, and `Edge-R2`.
- `Edge-R1` and `Edge-R2` advertise `192.168.1.0/24` into OSPF area 0, marking `GigabitEthernet0/0/1` as `passive-interface` so HSRP hello multicast packets are not mixed with OSPF hellos.
- `Core-R3` has dual equal-cost paths to `192.168.1.0/24` (or deterministic routing via both gateways), ensuring two-way convergence regardless of which router acts as Active HSRP forwarder.

## 4. Starter vs. Completed States
- **Starter State (`starter.pkt`):**
  - All cabling in place and interfaces addressed.
  - OSPF area 0 active across Core-R3, Edge-R1, and Edge-R2.
  - End hosts `PC1` and `PC2` configured with default gateway pointing to `192.168.1.1`.
  - HSRP is unconfigured on `Edge-R1` and `Edge-R2`.
  - NEG-01: Ping from `PC1` to `192.168.1.1` fails with 100% loss because no device responds to ARP for the virtual IP.
- **Completed State (`completed.pkt`):**
  - `Edge-R1` configured with `standby version 2`, `standby 1 ip 192.168.1.1`, `standby 1 priority 110`, `standby 1 preempt`.
  - `Edge-R2` configured with `standby version 2`, `standby 1 ip 192.168.1.1`, `standby 1 priority 100`, `standby 1 preempt`.
  - `Edge-R1` converges to `Active` state; `Edge-R2` converges to `Standby` state.
  - POS-01: Ping from `PC1` to `192.168.1.1` succeeds (4/4 packets, 100%).
  - POS-02: Ping from `PC1` to `203.0.113.100` succeeds (4/4 packets, 100%).
  - POS-03: `show standby brief` on `Edge-R1` confirms Active state.
  - POS-04: `show standby brief` on `Edge-R2` confirms Standby state.
  - POS-05: When `Edge-R1` Gi0/0/1 is shut down, `Edge-R2` transitions to Active, and `PC1` connectivity to `203.0.113.100` is preserved.
  - POS-06: When `Edge-R1` Gi0/0/1 is restored, preemption returns `Edge-R1` to Active state.

## 5. Automated Verification Strategy
- Run simulation script through Packet Tracer IPC:
  1. Clean canvas and place all 7 devices.
  2. Wire Ethernet links.
  3. Configure IP addressing, host settings, and OSPF routing.
  4. Save `starter.pkt`.
  5. Test NEG-01 (ping to 192.168.1.1 fails before HSRP configuration).
  6. Apply HSRP configuration to `Edge-R1` and `Edge-R2`.
  7. Fast-forward time for HSRP convergence.
  8. Capture canvas screenshot `topology.png`.
  9. Verify POS-01 through POS-04.
  10. Execute deliberate failover (shutdown `Edge-R1` LAN interface) and verify POS-05.
  11. Restore interface (`no shutdown`) and verify POS-06 preemption.
  12. Save `completed.pkt`.
  13. Export clean running configurations.
  14. Verify reload via independent script.
