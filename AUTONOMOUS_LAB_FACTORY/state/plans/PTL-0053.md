## 2. Learning Objectives & Curriculum Outcomes
- Architect and enforce a dedicated out-of-band management network design separating operational user traffic from infrastructure management planes.
- Isolate network device management Switched Virtual Interfaces (SVIs) on a dedicated, non-default Management VLAN (VLAN 99).
- Enforce strict cryptographic device management across Cisco IOS routers and switches using SSHv2 and disabling unencrypted Telnet (`transport input ssh`).
- Construct and bind VTY access class filters and edge access control lists preventing unauthorized data VLAN hosts from probing or accessing management interfaces.
- Diagnose and remediate management plane vulnerabilities including default VLAN 1 exposure, plaintext protocol acceptance, and missing VTY access-class restrictions.

## 4. Security & Management Specifications

### Credentials & Crypto:
- Domain Name: `enterprise.local`
- RSA Key: 1024 bits
- SSH Version: 2 (`ip ssh version 2`)
- Username: `admin` secret `Cisco12345!`
- Enable Secret: `Class12345!`
- VTY Configuration (R1-Edge, SW-Core, SW-Access):
  ```cisco
  line vty 0 4
   login local
   transport input ssh
   access-class 99 in
  ```

### Access Control Lists:
- **VTY Filter (ACL 99):**
  ```cisco
  access-list 99 permit host 192.168.99.10
  access-list 99 deny any
  ```
- **Edge Data Filter on `R1-Edge` Gi0/0.10 (`USER_FILTER`):**
  ```cisco
  ip access-list extended USER_FILTER
   remark Deny User Subnet from Reaching Management Subnet
   deny ip 192.168.10.0 0.0.0.255 192.168.99.0 0.0.0.255
   remark Permit User Subnet All Other Traffic
   permit ip 192.168.10.0 0.0.0.255 any
  ```

## 5. Starter Fault Injection

1. **Fault 1 (Switch Management on Default VLAN 1):**
   - On `SW-Access`, management IP `192.168.1.3/24` is configured on `Vlan 1` instead of `Vlan 99`, leaving the switch exposed on the unsegmented default VLAN.
2. **Fault 2 (Plaintext Telnet Enabled on SW-Core):**
   - On `SW-Core`, line vty has `transport input all` or `transport input telnet`, accepting unencrypted plaintext credentials.
3. **Fault 3 (Missing Access-Class Restriction on R1-Edge VTY):**
   - `R1-Edge` lacks `access-class 99 in` and `USER_FILTER` on Gi0/0.10, allowing `User-PC` to attempt administrative connections to `192.168.99.1`.

## 6. Verification Matrix

### Positive Verification (`completed.pkt`):
1. **POS-01:** `Admin-PC` pings `192.168.99.1` (R1-Edge), `192.168.99.2` (SW-Core), and `192.168.99.3` (SW-Access) (0% loss).
2. **POS-02:** `Admin-PC` connects to `192.168.99.1` via SSH (`ssh -l admin 192.168.99.1`).
3. **POS-03:** `Admin-PC` connects to `192.168.99.2` via SSH (`ssh -l admin 192.168.99.2`).
4. **POS-04:** `Admin-PC` connects to `192.168.99.3` via SSH (`ssh -l admin 192.168.99.3`).
5. **POS-05:** `User-PC` pings its default gateway `192.168.10.1` (0% loss).

### Negative / Boundary Verification (`completed.pkt`):
1. **NEG-01:** `User-PC` attempting to ping `192.168.99.1` is blocked by `USER_FILTER` (100% loss).
2. **NEG-02:** `User-PC` attempting to ping `192.168.99.2` or `192.168.99.3` is blocked by `USER_FILTER` (100% loss).
3. **NEG-03:** Telnet connections to `192.168.99.1`, `192.168.99.2`, and `192.168.99.3` are rejected / closed (`Closed by foreign host` / connection refused).

### Starter Fault Verification (`starter.pkt`):
1. **NEG-04:** Starter `SW-Access` accepts Telnet connection or runs on VLAN 1.
2. **NEG-05:** Starter `R1-Edge` Gi0/0.10 has no inbound filter, permitting `User-PC` to probe management gateway.
