## 2. Technical Scope & Learning Objectives
- **Scope:** Diagnose and resolve packet filtering faults in standard and extended IPv4 Access Control Lists on a multi-interface branch router. Troubleshoot rule order shadowing, interface directional misapplication (`in` vs `out`), and wildcard mask inversion in VTY line management filtering against an authoritative enterprise Traffic Policy Matrix.
- **Learning Objectives:**
  1. Correlate observable network connectivity symptoms against an authoritative business Traffic Policy Matrix.
  2. Identify shadowed Access Control Entries (ACEs) where broad deny statements precede specific permit statements.
  3. Correct ACL placement and direction (`in` vs `out`) on router ingress interfaces.
  4. Identify and correct wildcard mask errors and host filtering mistakes on standard ACLs securing VTY management lines.
  5. Validate packet filtering enforcement and rule hit counters using `show access-lists` and end-to-end traffic probes.

## 6. Injected Faults (Starter State)
1. **Fault 1 (Rule Shadowing):** In `SALES-FILTER`, `10 deny ip 192.168.10.0 0.0.0.255 192.168.30.0 0.0.0.255` precedes `20 permit tcp ... host 192.168.30.10 eq 80`, causing all web traffic to be blocked.
2. **Fault 2 (Directional Misplacement):** On `Gi0/0/0`, ACL is applied as `ip access-group SALES-FILTER out` instead of `in`.
3. **Fault 3 (Wildcard Inversion on VTY):** Standard ACL `10` uses `permit 192.168.20.0 255.255.255.0` (inverted mask) instead of `permit host 192.168.20.10`, locking out the administrator.

## 7. Remediation Plan (Completed State)
1. Remove `ip access-group SALES-FILTER out` and apply `ip access-group SALES-FILTER in` on `Gi0/0/0`.
2. Delete shadowed deny rule `10` from `SALES-FILTER` and insert it after the permit rule (`30 deny ip ...`).
3. Replace standard ACL `10` with `permit host 192.168.20.10`.
4. Validate hit counters and traffic matrix compliance.
