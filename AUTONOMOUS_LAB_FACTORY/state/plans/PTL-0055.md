# Implementation Plan: PTL-0055 — Integrated Branch Network Troubleshooting Challenge

## Lab Overview
- **Lab ID:** PTL-0055
- **Title:** Integrated Branch Network Troubleshooting Challenge
- **Category:** routing
- **Difficulty:** advanced
- **Slug:** integrated-branch-network-troubleshooting-challenge
- **Estimated Time:** 75 minutes
- **Prerequisites:** PTL-0052 (DHCP Relay Troubleshooting Across VLANs)

## Learning Objectives
1. Perform multi-domain fault isolation across Layer 2 switching (VLAN trunking), Layer 3 routing, network services (DHCP relay), and network security (ACLs).
2. Diagnose and restore 802.1Q trunk allowed-VLAN pruning issues isolating departmental subnets.
3. Validate and reconfigure Cisco IOS DHCP relay (`ip helper-address`) forwarding cross-subnet requests to a centralized DHCP server.
4. Troubleshoot and correct asymmetric or mispointed static return routes preventing bidirectional WAN reachability.
5. Analyze and modify extended access control lists (ACLs) to eliminate unintended protocol filtering while maintaining enterprise access control policy.

## Topology & Device Layout
```
[ HQ-Server ] (10.0.1.100/24, GW: 10.0.1.1)
      | Fa0
      | Gi0/0
[ HQ-R1 ] (Cisco 2911) [DHCP Pools: 192.168.10.0/24, 192.168.20.0/24]
      | Gi0/1 (WAN: 10.1.12.1/30)
      |
      | Gi0/1 (WAN: 10.1.12.2/30)
[ Branch-R2 ] (Cisco 2911)
      | Gi0/0 (802.1Q Trunk: Gi0/0.10, Gi0/0.20)
      | Gi0/1
[ Branch-SW1 ] (Catalyst 2960-24TT)
      |-- Fa0/10 (VLAN 10 Access) <---> [ Staff-PC1 ] (DHCP: 192.168.10.x/24)
      +-- Fa0/20 (VLAN 20 Access) <---> [ Eng-PC2 ] (Static: 192.168.20.10/24, GW: 192.168.20.1)
```

## IP Addressing Plan
- **HQ Server LAN:** `10.0.1.0/24`
  - `HQ-R1 Gi0/0`: `10.0.1.1/24`
  - `HQ-Server Fa0`: `10.0.1.100/24`, Default Gateway: `10.0.1.1`
- **WAN Transit:** `10.1.12.0/30`
  - `HQ-R1 Gi0/1`: `10.1.12.1/30`
  - `Branch-R2 Gi0/1`: `10.1.12.2/30`
- **Branch VLAN 10 (Staff):** `192.168.10.0/24`
  - `Branch-R2 Gi0/0.10`: `192.168.10.1/24`, `ip helper-address 10.0.1.1`
  - `Staff-PC1 Fa0`: Dynamic via DHCP (`192.168.10.50` - `192.168.10.150`), GW: `192.168.10.1`
- **Branch VLAN 20 (Engineering):** `192.168.20.0/24`
  - `Branch-R2 Gi0/0.20`: `192.168.20.1/24`
  - `Eng-PC2 Fa0`: `192.168.20.10/24`, Default Gateway: `192.168.20.1`

## Fault Injection Plan (`starter.pkt`)
1. **Fault 1 (Layer 2 Trunk Pruning):** `Branch-SW1` trunk interface `Gi0/1` is configured with `switchport trunk allowed vlan 10`, inadvertently pruning VLAN 20 from traversing the router-on-a-stick link.
2. **Fault 2 (Network Services / DHCP Relay):** `Branch-R2` subinterface `Gi0/0.10` lacks the `ip helper-address 10.0.1.1` command, leaving `Staff-PC1` without dynamic IPv4 parameters.
3. **Fault 3 (Layer 3 Routing):** `HQ-R1` has an erroneous static summary route pointing to a non-existent next-hop (`ip route 192.168.0.0 255.255.0.0 10.1.12.6`), causing blackholing of return packets from HQ to Branch subnets.
4. **Fault 4 (Network Security / ACL):** `Branch-R2` has an outbound access list `EDGE_FILTER` applied to `Gi0/1` that explicitly filters ICMP traffic to the corporate server:
   `access-list 101 deny icmp any host 10.0.1.100`
   `access-list 101 permit ip any any`

## Verification Strategy
- **POS-01:** `Staff-PC1` successfully receives dynamic IPv4 parameters in VLAN 10 via DHCP.
- **POS-02:** `Staff-PC1` achieves 0% packet loss pinging default gateway `192.168.10.1`.
- **POS-03:** `Eng-PC2` achieves 0% packet loss pinging default gateway `192.168.20.1`.
- **POS-04:** `Eng-PC2` successfully pings `Staff-PC1` across inter-VLAN subinterfaces.
- **POS-05:** `Eng-PC2` successfully pings `HQ-Server` (`10.0.1.100`) across the WAN.
- **POS-06:** `Staff-PC1` successfully pings `HQ-Server` (`10.0.1.100`) across the WAN.
- **NEG-01:** In starter state, `Branch-SW1` trunk restricts VLAN 20 (`Eng-PC2` ping to `192.168.20.1` drops 100%).
- **NEG-02:** In starter state, `Branch-R2` lacks DHCP helper (`Staff-PC1` fails to obtain dynamic lease).
- **NEG-03:** In starter state, `HQ-R1` invalid static route drops return traffic to branch subnets.
- **NEG-04:** In starter state, `Branch-R2` edge ACL drops ICMP echo requests to `HQ-Server`.
