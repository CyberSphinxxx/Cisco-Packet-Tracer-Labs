# Lab Design Plan: PTL-0031 - OSPFv2 Neighbor Adjacency Troubleshooting

## 1. Overview and Rationale
- **Lab ID:** PTL-0031
- **Slug:** `ospfv2-neighbor-adjacency-troubleshooting`
- **Category:** `routing`
- **Difficulty:** Intermediate
- **Estimated Minutes:** 60
- **Curriculum Objective:** Provide practical troubleshooting experience isolating and resolving common OSPFv2 neighbor formation failures. Learners diagnose Hello/Dead timer mismatches, Area ID mismatches, and passive interface misconfigurations on transit circuits to restore full routing convergence.

## 2. Topology and IP Addressing
- **Topology:**
  - `HQ-R1` (Cisco 4321 ISR, x: 380, y: 150) - Central Hub
  - `Branch-R2` (Cisco 4321 ISR, x: 180, y: 280) - Branch Spoke 1
  - `Remote-R3` (Cisco 4321 ISR, x: 580, y: 280) - Remote Spoke 2
  - `S1` (Catalyst 2960-24TT, x: 180, y: 400)
  - `S2` (Catalyst 2960-24TT, x: 580, y: 400)
  - `PC-Branch` (PC-PT, x: 180, y: 490)
  - `Server-Remote` (Server-PT, x: 580, y: 490)
- **Addressing:**
  - Transit Circuit 1 (`HQ-R1` Gi0/0/0 <-> `Branch-R2` Gi0/0/0): `10.1.12.0/30`
    - `HQ-R1` Gi0/0/0: `10.1.12.1/30`
    - `Branch-R2` Gi0/0/0: `10.1.12.2/30`
  - Transit Circuit 2 (`HQ-R1` Gi0/0/1 <-> `Remote-R3` Gi0/0/0): `10.1.13.0/30`
    - `HQ-R1` Gi0/0/1: `10.1.13.1/30`

## 3. Deliberate Injected Faults (Starter State)
- **Fault 1 (Timer Mismatch on Link 1):**
  - `Branch-R2` `Gi0/0/0` is configured with `ip ospf hello-interval 5` and `ip ospf dead-interval 20`.
  - `HQ-R1` `Gi0/0/0` uses default timers (`Hello 10`, `Dead 40`).
  - Result: Neighbors cannot form adjacency; `show ip ospf neighbor` is empty on Link 1.
- **Fault 2 (Area ID Mismatch on Link 2):**
  - `Remote-R3` has `network 10.1.13.0 0.0.0.3 area 1`.
  - `HQ-R1` has `network 10.1.13.0 0.0.0.3 area 0`.
  - Result: Packet Tracer drops Hellos due to Area mismatch; neighbor table is empty on Link 2.
- **Fault 3 (Missing LAN Network on Remote-R3):**
  - `Remote-R3` has omitted `network 192.168.3.0 0.0.0.255 area 0`.
  - Result: Even when Link 2 adjacency is restored, the remote LAN subnet is not advertised until corrected.

## 4. Completed Troubleshooting State
- **Fix 1:** Reset timers on `Branch-R2` `Gi0/0/0` to match `HQ-R1` (`ip ospf hello-interval 10`, `ip ospf dead-interval 40`).
- **Fix 2:** Update `Remote-R3` OSPF process so `10.1.13.0/30` is assigned to `area 0`.
- **Fix 3:** Add `network 192.168.3.0 0.0.0.255 area 0` to `Remote-R3` and configure passive-interfaces on LAN segments.
- Result: Full dual neighbor adjacency on `HQ-R1`, all subnets in routing tables, end-to-end ping succeeds.

## 5. Test Matrix
- **POS-01:** Direct Layer 3 link pings (`10.1.12.2` and `10.1.13.2` from HQ-R1).
- **POS-02:** `show ip ospf neighbor` on `HQ-R1` verifying FULL adjacencies with both `Branch-R2` (`2.2.2.2`) and `Remote-R3` (`3.3.3.3`).
- **POS-03:** Interface timer verification (`show ip ospf interface`) confirming synchronized timers (10/40) across all links.
- **POS-04:** Routing table convergence (`show ip route ospf`) on all routers showing complete subnet reachability (`192.168.1.0/24`, `192.168.2.0/24`, `192.168.3.0/24`).
- **POS-05:** End-to-end host communication (`PC-Branch` pinging `Server-Remote` at `192.168.3.10` and `HQ-R1` loopback `192.168.1.1`).
- **NEG-01:** Starter state fault demonstration: show zero OSPF neighbors on `HQ-R1` and demonstrate ping failure across spokes.
- **NEG-02:** Injection of MTU/passive fault: temporarily apply passive-interface on Link 1 transit, observe adjacency drop, and recover.
