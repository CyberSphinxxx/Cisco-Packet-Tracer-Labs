# Lab Implementation Plan: PTL-0028

**Lab ID:** `PTL-0028`  
**Lab Title:** Floating Static Routes and Administrative Distance  
**Category:** `routing`  
**Difficulty:** Intermediate  
**Estimated Time:** 60 minutes  
**Candidate Status:** Approved  

---

## 1. Educational Objectives & Scope
- Teach the role of Administrative Distance (AD) in Cisco IOS route selection and convergence.
- Configure primary static routes (default AD 1) across a primary enterprise WAN link.
- Configure floating static routes with elevated AD (AD 5) across a secondary backup link.
- Implement dual-homed edge-to-provider connectivity between `Edge-R1` and `ISP-R2`.
- Verify automatic failover to the floating route when the primary link fails.
- Verify automatic preemption and restoration to the primary path when the primary link recovers.
- Validate end-to-end client-server connectivity before failover, during failover, and after link restoration.

2. Connect cables (Copper Straight-Through).
3. Provision starter state:
   - Interfaces configured with IP addresses.
   - Primary static routes configured (AD 1).
   - Floating backup routes omitted.
4. Capture `topology.png` and save `starter.pkt`.
5. Apply solution state:
   - Configure floating static routes with AD 5 on `Edge-R1` and `ISP-R2`.
   - Save running configs.
6. Run verification matrix:
   - POS-01: Primary and backup link pings.
   - POS-02: Normal routing table (AD 1 active, AD 5 dormant) and PC-1 -> Web-Server traceroute.
   - POS-03: Primary link failure (`shutdown` Gi0/0) -> floating route activation `[5/0]` -> traceroute verification.
   - POS-04: Primary link recovery (`no shutdown` Gi0/0) -> preemption -> traceroute verification.
   - NEG-01: Both links down -> route purging and ping timeout.
   - NEG-02: Equal AD comparison.
7. Save `completed.pkt`.
8. Export clean configs (`configs/Edge-R1.txt`, `configs/ISP-R2.txt`).
9. Author `metadata.json`, `README.md`, `verification.md`, and `PTL-0028-SIMULATOR-RESULTS.md`.
