# Lab Design Plan: PTL-0030 - OSPFv2 Passive Interfaces and Neighbor Control

## 1. Overview and Rationale
- **Lab ID:** PTL-0030
- **Slug:** `ospfv2-passive-interfaces-and-neighbor-control`
- **Category:** `routing`
- **Difficulty:** Intermediate
- **Estimated Minutes:** 60
- **Curriculum Objective:** Teach the operational necessity, security implications, and configuration of OSPFv2 passive interfaces. Explain how passive interfaces suppress Hello packet transmissions to prevent rogue neighbor formation and bandwidth/CPU waste on access links while continuing to advertise the attached subnet as a stub network in the Link-State Database (LSDB).

## 2. Topology and IP Addressing
- **Topology:**
  - `Edge-R1` (Cisco 4321 ISR, x: 200, y: 220)
  - `Core-R2` (Cisco 4321 ISR, x: 500, y: 220)
  - `S1` (Cisco Catalyst 2960-24TT, x: 200, y: 350)
  - `S2` (Cisco Catalyst 2960-24TT, x: 500, y: 350)
  - `PC-1` (PC-PT, x: 200, y: 450)
  - `Server-1` (Server-PT, x: 500, y: 450)
- **Addressing:**
  - Transit Link (R1 Gi0/0/1 <-> R2 Gi0/0/1): `10.0.0.0/30`
    - `Edge-R1` Gi0/0/1: `10.0.0.1/30`
    - `Core-R2` Gi0/0/1: `10.0.0.2/30`
  - Edge LAN (R1 Gi0/0/0 <-> S1 Fa0/1 <-> PC-1 Fa0): `192.168.10.0/24`
    - `Edge-R1` Gi0/0/0: `192.168.10.1/24`
    - `PC-1` Fa0: `192.168.10.10/24`, Gateway: `192.168.10.1`
  - Core LAN (R2 Gi0/0/0 <-> S2 Fa0/1 <-> Server-1 Fa0): `192.168.20.0/24`
    - `Core-R2` Gi0/0/0: `192.168.20.1/24`
    - `Server-1` Fa0: `192.168.20.10/24`, Gateway: `192.168.20.1`

## 3. Staging and Solution State
- **Starter State (`starter.pkt`):**
  - Full IP addressing and baseline OSPF Area 0 configured on `Edge-R1` and `Core-R2`.
  - All interfaces (`Gi0/0/0` and `Gi0/0/1`) are active in OSPF without passive interfaces.
  - OSPF Hellos are being sent out `Gi0/0/0` towards end devices.
- **Completed State (`completed.pkt`):**
  - Edge-R1: `passive-interface GigabitEthernet0/0/0` under `router ospf 1`.
  - Core-R2: `passive-interface default` followed by `no passive-interface GigabitEthernet0/0/1` under `router ospf 1`.
  - Both LAN interfaces are confirmed passive ("No Hellos (Passive interface)").
  - Inter-router transit neighbor adjacency remains `FULL`.
  - LAN subnets (`192.168.10.0/24` and `192.168.20.0/24`) remain fully reachable across OSPF.

## 4. Test Matrix
- **POS-01:** Point-to-point transit link ping and local gateway pings.
- **POS-02:** OSPF neighbor table verification (`show ip ospf neighbor`) showing `FULL` adjacency across `Gi0/0/1`.
- **POS-03:** Interface OSPF verification (`show ip ospf interface GigabitEthernet0/0/0`) showing `No Hellos (Passive interface)` on Edge-R1 and Core-R2.
- **POS-04:** Interface OSPF verification on transit link (`show ip ospf interface GigabitEthernet0/0/1`) showing active hello timers (`Timer intervals configured, Hello 10, Dead 40`).
- **POS-05:** Routing table inspection (`show ip route ospf`) showing `192.168.10.0/24` learned on Core-R2 and `192.168.20.0/24` learned on Edge-R1.
- **POS-06:** End-to-end data plane reachability: `PC-1` ping to `Server-1` (`192.168.20.10`).
- **NEG-01:** Transit link inadvertent passive configuration: making `Gi0/0/1` passive tears down the neighbor relationship and withdraws remote routes.
- **NEG-02:** Transit link un-passive restoration: removing passive status restores adjacency and routes.
