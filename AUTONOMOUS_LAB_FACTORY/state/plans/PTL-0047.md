## Problem Statement & Educational Value
Variable Length Subnet Masking (VLSM) enables network engineers to divide an assigned IPv4 network into non-uniform subnets that match exact host counts, eliminating the address wastage inherent in fixed-length subnetting. However, manual calculation errors frequently produce:
1. **Broadcast/Subnet ID Host Assignment**: Assigning the all-zeros subnet ID or all-ones broadcast address as a host IP.
2. **Subnet Mask Mismatches**: Endpoints and default gateways configured with conflicting subnet masks, causing asymmetric broadcast boundary calculations and failing ARP resolution.
3. **Prefix Length Over-Allocation**: Using an incorrect mask that overlaps with adjacent planned subnets or fails to accommodate the required host count.
4. **Point-to-Point WAN Misconfiguration**: Assigning masks looser than `/30` on point-to-point transit links or configuring gateway IPs outside the valid subnet block.

In this lab, learners are presented with an enterprise branch network provisioned from a base network of `192.168.100.0/24`. Learners audit the VLSM allocation table against actual device configurations, diagnose multiple addressing faults (broadcast IP host assignment on Engineering PC, subnet mask mismatch on Sales gateway, and transit subnet mask discrepancy on WAN link), remediate each issue with minimal non-disruptive configuration changes, and verify full end-to-end multi-subnet reachability.

## Fault Injection in Starter State
1. **Fault 1 (Broadcast IP Assigned to Host):** `PC-Eng1` is mistakenly configured with IP `192.168.100.63 255.255.255.192`. In IPv4, `.63` is the directed broadcast address of the `192.168.100.0/26` subnet, causing packet loss and broadcast anomalies.
2. **Fault 2 (Subnet Mask Mismatch on Gateway):** `R1 Gi0/0/1` is configured with `192.168.100.65 255.255.255.192` (`/26`) instead of `255.255.255.224` (`/27`). `PC-Sales1` uses `/27`. This mask mismatch causes boundary confusion and routing inconsistencies.
3. **Fault 3 (WAN Link Prefix Mismatch):** `R1 Gi0/0/2` is configured with `192.168.100.113 255.255.255.248` (`/29`) while `R2 Gi0/0/2` is configured with `192.168.100.114 255.255.255.252` (`/30`). The mask must be corrected to `/30` on R1 to preserve addressing efficiency.
